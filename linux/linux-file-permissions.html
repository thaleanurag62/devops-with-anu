Linux File Permissions

Linux file permissions are one of the most important concepts to understand when working with Linux systems. They control who can read, modify, or execute files and who can access directories.

In this guide: Learn Linux permissions from the basics, including read, write, execute, user/group/others, chmod, chown, chgrp, numeric permissions such as 755 and 644, directory permissions, and practical examples.

What Are Linux File Permissions?

Linux is a multi-user operating system. Different users and programs can work on the same computer or server, so Linux needs a way to control access to files and directories.

This is where file permissions are used.

Permissions determine whether a particular user can:

  • Read a file
  • Modify a file
  • Execute a file
  • Access or traverse a directory

Linux permissions are mainly divided into three categories:

  • User – the owner of the file
  • Group – users belonging to the file's group
  • Others – everyone else

How to Check File Permissions

The most common command used to view Linux file permissions is: 

ls -l

For example: 

ls -l notes.txt

You may see something similar to: 

-rw-r--r-- 1 anu devops 1200 Aug 8 10:30 notes.txt

The first part, -rw-r--r--, contains the file type and permissions.

Understanding the Permission String

Consider the following permission string: 

-rwxr-xr--

It can be divided into four parts: 

-   rwx   r-x   r--
|    |     |     |
|    |     |     └── Others
|    |     └──────── Group
|    └────────────── Owner
└─────────────────── File type

First Character – File Type

The first character identifies the type of filesystem object.

Symbol Meaning
- Regular file
d Directory
l Symbolic link

For example: 

-rw-r--r--

The first - indicates that it is a regular file.

A directory may look like: 

drwxr-xr-x

Read, Write and Execute Permissions

Linux uses three basic permissions:

Permission Symbol Meaning
Read r Read or view contents
Write w Modify contents
Execute x Execute a program or traverse a directory

Read Permission – r

Read permission allows a user to read the contents of a file. 

r--

For a directory, read permission allows the user to list directory entries, subject to the other permissions involved.

Write Permission – w

Write permission allows modification of a file. 

-w-

For a directory, write permission allows entries to be created, deleted, or renamed when the necessary directory permissions are present.

Execute Permission – x

Execute permission allows an executable program or script to be run. 

--x

For directories, execute permission allows traversal through the directory.

User, Group and Others

Linux permissions are applied to three categories.

Category Symbol Meaning
User u File owner
Group g Members of the file's group
Others o Everyone else

For example: 

-rwxr-x---

This means:

  • Owner → read, write and execute
  • Group → read and execute
  • Others → no permissions

Linux Numeric Permissions

Linux permissions can also be represented using numbers.

Permission Value
Read (r) 4
Write (w) 2
Execute (x) 1

The values are added together to create a permission number. 

r-- = 4

-w- = 2

--x = 1

rw- = 4 + 2 = 6

r-x = 4 + 1 = 5

rwx = 4 + 2 + 1 = 7

Common Permission Values

Number Permission
0 ---
1 --x
2 -w-
3 -wx
4 r--
5 r-x
6 rw-
7 rwx

chmod Command

chmod means "change mode". It is used to change the permissions of files and directories.

Basic syntax: 

chmod [permissions] [file]

Example: 

chmod 755 script.sh

This changes the permissions of script.sh.

What Does chmod 755 Mean?

The three numbers represent: 

Owner   Group   Others
  7       5       5

Now calculate them: 

7 = rwx

5 = r-x

5 = r-x

Therefore: 

755 = rwxr-xr-x

The owner has read, write and execute permissions. Group and others have read and execute permissions.

What Does chmod 644 Mean?

chmod 644 file.txt

The permission breakdown is: 

6 = rw-

4 = r--

4 = r--

Therefore: 

644 = rw-r--r--

The owner can read and modify the file, while group and others can read it.

Symbolic chmod

Instead of numbers, you can use symbolic permissions.

For example, to add execute permission for the owner: 

chmod u+x script.sh

To add write permission for the group: 

chmod g+w file.txt

To remove write permission from others: 

chmod o-w file.txt

The commonly used operators are:

Operator Meaning
+ Add permission
- Remove permission
= Set exact permission

Examples

chmod u+x script.sh

chmod g-w file.txt

chmod o=r file.txt

chmod a+r file.txt

Here, a means all users.

chown Command

Permissions and ownership are related but different concepts.

The chown command changes the owner of a file or directory.

Example: 

sudo chown anu notes.txt

You can change both the owner and group: 

sudo chown anu:devops notes.txt

After this command: 

Owner = anu
Group = devops

chgrp Command

The chgrp command changes the group associated with a file. 

sudo chgrp developers project.txt

You can check the result using: 

ls -l project.txt

Linux Directory Permissions

Directory permissions work slightly differently from regular file permissions.

Read – r

Allows a user to list the directory's entries.

Write – w

Allows creation, deletion and renaming of entries when the required permissions are present.

Execute – x

Allows a user to enter or traverse the directory and access entries when the required permissions are satisfied.

Tip: When troubleshooting directory access, remember that a user may need execute permission on every relevant directory in the path to reach a file.

Practical Linux File Permission Example

Suppose you create a shell script: 

nano backup.sh

Check its permissions: 

ls -l backup.sh

You might see: 

-rw-r--r-- backup.sh

The owner does not have execute permission.

Add execute permission: 

chmod u+x backup.sh

Check again: 

ls -l backup.sh

The result may now look like: 

-rwxr--r-- backup.sh

The owner can now execute the script.

How to Troubleshoot "Permission Denied"

One of the most common Linux errors is: 

Permission denied

This usually means that the current user or process does not have the required access.

Start by checking the file: 

ls -l filename

Check:

  • Who owns the file?
  • Which group owns it?
  • What permissions are assigned?
  • Does the directory containing it allow traversal?

For a full path, this command can be helpful: 

namei -l /path/to/file

It shows permissions for each part of the path and can help identify where access is being blocked.

Why You Should Avoid chmod 777

Beginners sometimes use: 

chmod 777 file

This gives: 

rwxrwxrwx

That means the owner, group and others all receive read, write and execute permissions.

Security warning: Do not use chmod 777 as a general solution for permission problems. It may provide more access than necessary and can create security risks.

Instead, identify which user or process needs access and grant only the permissions required.

Why Linux File Permissions Matter in DevOps

File permissions are particularly important in DevOps and cloud environments.

Linux servers commonly contain:

  • Application files
  • Configuration files
  • Log files
  • SSH keys
  • Deployment scripts
  • Database credentials
  • Environment files

Incorrect permissions can cause deployment failures, application errors and security issues.

For this reason, understanding Linux permissions is useful when working with technologies such as servers, containers, CI/CD pipelines, cloud platforms and automation tools.

Frequently Asked Questions

What is chmod in Linux?
chmod is a Linux command used to change the permissions of files and directories. For example, chmod 755 script.sh changes the permissions of the script.
What does chmod 755 mean?
755 means the owner has read, write and execute permissions, while the group and others have read and execute permissions. The symbolic representation is rwxr-xr-x.
What does chmod 644 mean?
644 means the owner has read and write permissions, while group and others have read-only permission. Its symbolic representation is rw-r--r--.
What is the difference between chmod and chown?
chmod changes file or directory permissions, while chown changes the owner. For example, chmod 644 file.txt changes permissions and sudo chown anu file.txt changes ownership.
Why does Linux show Permission denied?
The current user or process may not have the required permission on the file, directory, or one of the directories in the path. Use ls -l and namei -l to investigate.
Is chmod 777 safe?
chmod 777 grants read, write and execute permissions to everyone. It should not be used unnecessarily because it can provide excessive access. Use the minimum permissions required instead.

Conclusion

Linux file permissions are a fundamental part of Linux system administration and security.

The basic permission model consists of: 

User + Group + Others

and the three fundamental permissions are: 

Read + Write + Execute

Once you understand permission strings such as: 

-rwxr-xr-x

and numeric modes such as: 

755
644
600

you will be able to understand and manage many common Linux access-control situations.

The most important commands to remember are: 

ls -l
chmod
chown
chgrp

Practice these commands in a Linux environment and always follow the principle of least privilege: give users and applications only the access they actually need.
