Linux Process Management

A process is a running instance of a program in a Linux system. Whenever you start an application, execute a command or run a background service, Linux creates and manages one or more processes.

In this guide: Learn what Linux processes are, understand PID and PPID, process states, foreground and background processes, and important commands such as ps, top, htop, jobs, bg, fg, kill, pkill, nohup, nice and renice.

What Is a Linux Process?

A process is a program that is currently executing. For example, when you open a terminal and run: 

ls

Linux creates a process to execute the command. After the command finishes, that process normally exits.

Long-running applications such as web servers, databases and system services can remain active for much longer periods.

Linux assigns each running process an identification number called a PID.

Program vs Process

A program is a set of instructions stored on disk. A process is an active execution of those instructions. 

Program
   ↓
Execution
   ↓
Process
   ↓
PID

PID and PPID

PID

PID stands for Process ID. It is a numeric identifier assigned to a process.

You can view processes and their PIDs with: 

ps

PPID

PPID stands for Parent Process ID. Many processes are created by another process, called their parent.

For example: 

Parent Process
      |
      └── Child Process

The relationship between processes can be useful when troubleshooting applications and services.

Linux Process States

Linux processes can move through different states during their lifetime. Common process states include:

State Meaning
R Running or runnable
S Interruptible sleep
D Uninterruptible sleep, often waiting for I/O
T Stopped or traced
Z Zombie process

Running

A process in the running or runnable state is executing or waiting for CPU time.

Sleeping

A sleeping process is waiting for an event, input or resource before it can continue.

Zombie

A zombie process has finished execution, but its parent has not yet collected its exit status.

Note: A small number of short-lived zombie processes can occur normally. Persistent zombie processes may indicate that a parent process is not properly handling child processes.

Foreground vs Background Processes

Foreground Process

A foreground process occupies the current terminal session and normally receives input from that terminal.

For example: 

ping example.com

You can stop or interrupt many foreground commands with: 

Ctrl + C

Background Process

A background process can continue running while you use the same shell. One simple way to start a command in the background is to append &. 

sleep 60 &

The shell will return control to you while the command runs.

The ps Command

The ps command provides a snapshot of currently running processes.

Basic usage: 

ps

This commonly shows processes associated with the current terminal.

View Processes for All Users

ps aux

This is one of the most commonly used forms of ps when troubleshooting a Linux system.

View a Full Process Listing

ps -ef

This displays processes in a different format and includes parent process information.

Useful ps Options

Command Purpose
ps Show processes associated with the current terminal
ps aux Show processes for all users
ps -ef Display a full-format process listing
ps -u username Show processes belonging to a specific user
ps -p PID Show information about a specific PID

Find a Specific Process

You can combine ps with tools such as grep: 

ps aux | grep nginx

This can help locate processes matching a particular name.

The top Command

The top command provides a continuously updating view of system processes and resource usage. 

top

It can help you identify processes consuming significant CPU or memory.

The display commonly includes information such as:

  • Process ID
  • User
  • CPU usage
  • Memory usage
  • Process state
  • Command name

To exit top, press: 

q

The htop Command

htop is an interactive process viewer that provides a more user-friendly interface than traditional top on systems where it is installed. 

htop

Depending on the distribution, you may need to install it first. For Debian or Ubuntu-based systems: 

sudo apt install htop

The exact installation command can differ between Linux distributions.

The jobs Command

The jobs command displays jobs started by the current shell.

For example: 

sleep 100 &

jobs

You may see something similar to: 

[1]+  Running    sleep 100 &

The number in brackets is the job ID for that shell.

The bg Command

The bg command resumes a stopped job in the background.

For example, start a command: 

sleep 100

Press: 

Ctrl + Z

This suspends the job. You can then run: 

bg

The job will continue in the background.

The fg Command

The fg command brings a background job into the foreground. 

fg

If you have multiple jobs, specify the job number: 

fg %1

The kill Command

The kill command sends a signal to a process. It does not always mean that the process is immediately terminated.

First identify the PID: 

ps

Then send a termination signal: 

kill PID

For example: 

kill 2450

Common Signals

Signal Name Purpose
15 SIGTERM Request graceful termination
9 SIGKILL Force termination when other methods fail
2 SIGINT Interrupt a process
19 SIGSTOP Stop a process
18 SIGCONT Continue a stopped process

Using SIGTERM

A graceful termination request can be sent explicitly: 

kill -15 PID

This gives the application an opportunity to perform cleanup.

Using SIGKILL

If a process does not respond to normal termination, an administrator may use: 

kill -9 PID
Use SIGKILL carefully. A process cannot catch or handle SIGKILL, so it does not get an opportunity to perform normal cleanup.

The pkill Command

The pkill command can send signals to processes based on their name or other matching criteria.

For example: 

pkill process_name

Because process-name matching can affect more than one process, verify the target carefully before using it on important systems.

The nohup Command

The nohup command allows a command to continue running even after the terminal session is closed, subject to the environment and how the process is launched.

Example: 

nohup python3 app.py &

By default, output may be redirected to a file such as nohup.out if standard output is not otherwise redirected.

A more explicit example is: 

nohup python3 app.py > app.log 2>&1 &

This sends standard output and standard error to app.log.

nice and Process Priority

Linux uses a scheduling priority mechanism called the nice value.

The nice value normally ranges from -20 to 19. Lower values represent higher scheduling priority, while higher values represent lower priority.

Nice Value General Meaning
-20 Highest priority
0 Default value
19 Lowest priority

Starting a Process with nice

nice -n 10 command

For example: 

nice -n 10 python3 script.py

This starts the command with a positive nice value, giving it a lower CPU scheduling priority relative to the default.

The renice Command

The renice command changes the nice value of an already running process.

First identify the PID: 

ps

Then: 

renice 10 -p PID

Changing a process to a higher priority may require appropriate privileges.

The pstree Command

The pstree command displays processes in a tree structure. This makes parent-child relationships easier to understand. 

pstree

You can also include process IDs: 

pstree -p

A simplified example: 

systemd
 ├── sshd
 │    └── bash
 │         └── python
 └── cron

The /proc Filesystem

Linux provides detailed information about processes through the virtual /proc filesystem.

For a process with PID 1234: 

ls /proc/1234

Useful files and directories include:

Path Information
/proc/PID/status Process status and related information
/proc/PID/cmdline Command-line information
/proc/PID/fd File descriptors used by the process
/proc/PID/cwd Current working directory link
/proc/PID/exe Executable associated with the process

Practical Process Management Example

Let's walk through a simple process-management workflow.

Step 1: Start a Test Process

sleep 300 &

Step 2: Check Background Jobs

jobs

Step 3: Find the Process

ps aux | grep sleep

Step 4: Identify the PID

Look at the process listing and identify the PID belonging to the sleep command.

Step 5: Request Termination

kill PID

Step 6: Verify

ps -p PID

If the process has exited, it should no longer appear as an active process.

Common Process Management Problems

High CPU Usage

If a system becomes slow, start by identifying processes using significant CPU resources. 

top

or: 

ps aux --sort=-%cpu

High Memory Usage

To view processes sorted by memory usage: 

ps aux --sort=-%mem

A Process Will Not Stop

Try a normal termination signal first: 

kill PID

If the process does not terminate and you have determined that forceful termination is appropriate: 

kill -9 PID

Find Which Process Uses a Port

On systems with the appropriate tools installed, you can use: 

ss -ltnp

This can help identify listening TCP services and associated processes when sufficient privileges are available.

Linux Process Management Best Practices

1. Identify Before Terminating

Always verify the PID and command before sending a signal.

2. Prefer Graceful Termination

Use the default kill PID or SIGTERM before using SIGKILL.

3. Avoid Unnecessary Root Privileges

Use sudo only when administrative privileges are actually required.

4. Monitor Resource Usage

Commands such as top, htop and ps are useful when diagnosing CPU and memory problems.

5. Be Careful with pkill

A name-based command can potentially match multiple processes. Always confirm what will be affected.

6. Test Commands Safely

Practice process-management commands using test processes or a virtual machine before applying unfamiliar commands to production systems.

Frequently Asked Questions

What is a process in Linux?
A process is a running instance of a program. Linux assigns each process a unique process ID, or PID.
What is a PID in Linux?
PID stands for Process ID. It is a numeric identifier used by Linux to identify a running process.
What does the ps command do?
The ps command provides a snapshot of running processes. Commands such as ps aux can show processes belonging to all users.
What is the difference between ps and top?
ps generally provides a snapshot of processes, while top provides an interactive display that updates periodically.
What is the difference between a foreground and background process?
A foreground process normally uses the current terminal for interaction. A background process can continue running while the shell accepts other commands.
What does kill do in Linux?
The kill command sends a signal to a process identified by its PID. The default signal is normally SIGTERM.
What is kill -9?
kill -9 sends SIGKILL, which forcefully terminates a process. It should be used carefully because the process cannot handle or clean up from SIGKILL.
What is nohup used for?
nohup can help a command continue running after a terminal hangup. It is commonly combined with background execution using &.
What are nice and renice?
nice starts a process with a specified nice value, while renice changes the nice value of an already running process.
What is a zombie process?
A zombie is a process that has finished execution but whose parent has not yet collected its exit status.

Conclusion

Linux process management is an essential skill for anyone working with Linux servers, DevOps, cloud infrastructure or system administration.

Understanding processes helps you monitor applications, identify resource-intensive workloads, troubleshoot problems and safely control running programs.

The most important commands to remember are: 

ps
top
htop
jobs
bg
fg
kill
pkill
nohup
nice
renice
pstree

Start by learning ps, top, jobs, kill and nohup. Once these commands become familiar, move on to process priorities, the /proc filesystem and more advanced troubleshooting techniques.

The safest way to practice process management is with test processes or a virtual machine, especially when learning commands that can terminate or modify running processes.
