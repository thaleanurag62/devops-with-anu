Linux File System Hierarchy Explained

By Anurag Thale·Updated August 2026·10 min read

One of the first things that confuses people coming from Windows is that Linux has no drive letters — no C:\, no D:\. Instead, everything on a Linux system lives under a single root directory, written as /. Every disk, partition, and device gets "mounted" somewhere inside this one unified tree. Once you understand this structure, navigating any Linux system — from a Raspberry Pi to an AWS EC2 instance — becomes second nature.

The root directory: everything starts at /

In Linux, / (pronounced "root") is the top of the entire file system. Every single file, folder, and device on the system exists somewhere underneath it. Run ls / on almost any Linux machine and you'll see a familiar, standardized set of folders — this is called the Filesystem Hierarchy Standard (FHS), and nearly every major distribution follows it.

$ ls /
bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var

The essential directories, explained

DirectoryWhat it holds
/binEssential command binaries usable by all users (ls, cp, cat)
/sbinSystem binaries mainly for the root/admin user (fdisk, reboot)
/etcSystem-wide configuration files (network configs, service configs)
/homePersonal directories for each user (e.g. /home/anu)
/rootThe home directory for the root (admin) user only
/varVariable data that changes often — logs, caches, mail queues
/tmpTemporary files, usually cleared on reboot
/usrUser-installed programs and their supporting files
/optOptional/third-party software not managed by the package manager
/devDevice files representing hardware (disks, terminals)
/procVirtual files exposing live kernel and process information
/mnt, /mediaMount points for external and removable storage
Real-world tip: If a server is running low on disk space, /var/log is almost always the first place to check — log files can grow silently for months if log rotation isn't configured properly.

A closer look at /etc — the config directory

/etc is arguably the directory you'll touch most as a sysadmin or DevOps engineer. It holds plain-text configuration files for nearly every service on the system:

  • /etc/passwd — list of user accounts
  • /etc/hosts — manual hostname-to-IP mappings
  • /etc/ssh/sshd_config — SSH server configuration
  • /etc/nginx/ — Nginx web server configuration (if installed)
  • /etc/fstab — defines which disks/partitions mount where at boot

A closer look at /var — the "changing" directory

Where /etc holds configuration that rarely changes, /var holds data that changes constantly during normal operation:

  • /var/log — system and application logs
  • /var/www — common location for web server files
  • /var/cache — cached data used to speed up applications
  • /var/spool — queued tasks like print jobs or mail

Absolute vs relative paths

Understanding paths is just as important as understanding the folders themselves.

  • Absolute path — starts from root: /home/anu/projects/notes.txt
  • Relative path — starts from your current location: projects/notes.txt

Two special shortcuts you'll use constantly: . means "current directory" and .. means "one directory up."

$ pwd
/home/anu/projects

$ cd ..
$ pwd
/home/anu

Why this matters in DevOps

Nearly every deployment, Docker image, and server troubleshooting session assumes you already know this map. Application configs live in /etc, logs live in /var/log, web files often live in /var/www or /srv, and temporary build artifacts land in /tmp. When something breaks in production, knowing exactly where to look — instead of guessing — is what separates a five-minute fix from a two-hour one.

Key takeaways

  • Linux has one unified directory tree starting at / — no drive letters.
  • The Filesystem Hierarchy Standard (FHS) keeps directory structure consistent across distributions.
  • /etc holds configuration, /var holds changing data like logs, /home holds user files.
  • Knowing absolute vs relative paths is essential for navigating and scripting.
